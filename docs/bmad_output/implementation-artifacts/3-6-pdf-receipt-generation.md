# Story 3.6: PDF Receipt Generation

Status: ready-for-dev

<!-- Note: Validation is optional. Run validate-create-story for quality check before dev-story. -->

## Story

As an **authenticated subscriber**,
I want to download a PDF receipt for each completed recharge transaction,
so that I have a permanent record for my financial records.

## Acceptance Criteria

1. **Given** a recharge transaction is completed, **When** the subscriber clicks the receipt download link (`receipt_url`), **Then** `GET /api/v1/subscriber/receipts/{transaction_id}` generates and streams a PDF receipt (FR-15). [Source: epics.md:1286; prd.md FR-15 (lines 282, 288)]
2. **And** the PDF contains: subscriber name (decrypted), MSISDN[-4:], transaction date (IST), plan name, amount paid (INR), payment method type, transaction ID, operator logo placeholder. [Source: epics.md:1288]
3. **And** the PDF is generated by WeasyPrint from an HTML template. [Source: epics.md:1290]
4. **And** the response Content-Type is `application/pdf` with `Content-Disposition: attachment; filename="receipt_{transaction_id}.pdf"`. [Source: epics.md:1292]
5. **And** PII (full MSISDN, full name) in the PDF is limited to what is legally required; no card numbers appear. [Source: epics.md:1294; prd.md FR-15 (line 289), FR-64 (line 822)]

## Dev Notes

### Scope boundary

- **DOES:** `GET /receipts/{transaction_id}` (WeasyPrint HTML→PDF stream), receipt HTML template, PII decrypt/mask, Content-Type/Disposition, frontend download link, tests.
- **DOES NOT:** S3 receipt storage (`s3_key` stays null for MVP — on-demand generation), recharge write (3-5), transaction ledger (3-3), refund view (3-7).

### WeasyPrint — declared but gated from the tox test env

`weasyprint>=62` is in `pyproject.toml:25` but excluded from the tox test env (`pyproject.toml:298-301`). Two options: (a) add `weasyprint` to the test env deps so an integration test renders a real PDF; (b) mock the render in unit tests (assert template context + headers, stub `write_pdf`). Recommend (b) for unit tests + one `slow` integration with real WeasyPrint. Document the choice. [Source: pyproject.toml:25, 298-301; architecture.md:107, 1458; app_code_toolchain memory]

### On-demand generation, no S3 in MVP

`recharge_receipts` (`V1:295-308`) has `s3_key` but no `pdf_blob`; there is no boto3/S3 client in the repo. Generate the PDF on each GET (deterministic from order data — idempotent), leave `s3_key` null. S3 persistence is deferred. [Source: V1:295-308; service_webapp/pyproject.toml (no boto3)]

### PII decryption — use decrypt_pii (AES-256-GCM)

`subscriber_name` is stored encrypted (urlsafe-base64 `nonce‖ct‖tag`) and read via `decrypt_pii` (`core/security.py:127-129`). The 1-9 story prose mentions `pgp_sym_decrypt` — that is **outdated**; the actual implementation is app-layer AES-GCM. Use `decrypt_pii`. [Source: core/security.py:127-129; 1-6 story; 1-9 story (outdated prose)]

### Auth & owner assertion

`require_role("subscriber")` + assert `recharge_orders.subscriber_id == jwt.sub` (load the order first, then check ownership via the `_require_sub` pattern). [Source: core/auth.py:129-178; account.py:217-231; V1:276-290; deferred-work D3]

### Project Structure Notes

- **NEW:** `service_webapp/src/receipts/template.html` (+ render helper); `GET /receipts` on `routers/recharge.py` (extend).
- **MODIFIES:** `service_webapp/src/db/recharge/queries.py` (receipt read); `pyproject.toml` (test env: weasyprint or mock); `frontend/src/lib/api.ts` (`getReceipt`).
- **Variances flagged:** WeasyPrint gated from test env (mock or add dep); no S3 (on-demand); `decrypt_pii` not `pgp_sym_decrypt`.
